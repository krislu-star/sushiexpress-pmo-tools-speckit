## 1. 概述 (Overview)

001 版的儀表板資料來自人工從 Google Sheets 下載四個分頁的 CSV，再轉換、重新產出頁面，每次更新都仰賴專人操作，也容易忘記或漏掉分頁。頁面內含爭鮮真實工作資料，目前僅靠放置位置限制閱覽者。本功能讓儀表板**依排程自動取得最新的工作表內容**，並確保**只有授權人員能看到案件資料**。

## 2. 問題陳述 (Problem Statement)

**目前狀況**：
- 更新資料需手動下載四個 CSV、執行轉換、重新產出並交付，步驟多且依賴特定人員。
- 頁面資料的新舊取決於上次有人手動更新的時間，會議前可能看到過期內容。
- 頁面本身沒有存取控制；知道網址的人即可看到全部案件。

**期望狀況**：
- 在約定的時間（例如雙週會前）自動取得工作表最新內容並更新儀表板，無需人工匯出。
- 工作表內容有誤時，不發佈錯誤資料，並通知負責人哪一分頁、哪一列需要修正。
- 未授權者無法取得案件資料（不只是看不到畫面，而是拿不到資料本身）。

**影響範圍**：資料維護者（各小組填寫工作表的同仁）、儀表板維運者、所有閱覽者。

## 3. 使用者故事 (User Stories)

### US-001: 自動取得最新工作表內容
```
身為儀表板維運者,
我希望儀表板依排程自動讀取工作表四個分頁並更新,
以便不必每次手動下載 CSV，會議前看到的都是最新內容。
```

**驗收標準**:
- [ ] 依約定排程自動讀取 Frontend、Project、BPM、SAP 四個分頁
- [ ] 讀取結果套用 001 的資料規則（欄位、Progress、燈號、略過空白列、保留原表列號）
- [ ] 更新後，頁面顯示的擷取日期為本次讀取的日期
- [ ] 維運者可在排程以外手動觸發一次更新

### US-002: 錯誤資料不上線並通知
```
身為資料維護者,
我希望工作表內容有誤時，儀表板維持上一版並告訴我哪裡要修,
以便錯誤不會出現在主管或會議畫面上。
```

**驗收標準**:
- [ ] 任一分頁無法讀取或內容不合規則時，本次更新不發佈，線上維持上一版
- [ ] 通知內容指出分頁、原表列號、欄位與原始值
- [ ] 分頁缺少 Progress／燈號欄時可照常更新，但通知中列出缺欄的分頁
- [ ] 每次更新（含成功）都寄出通知，主旨標示成功／有警告／失敗與日期

### US-003: 只有授權人員能看到案件資料
```
身為資訊主管,
我希望只有授權人員能開啟儀表板並看到案件內容,
以便真實工作資料不會外流給知道網址的其他人。
```

**驗收標準**:
- [ ] 未通過驗證者開啟任一頁面時，看不到任何案件內容，且無法由網頁原始碼或傳輸內容取得案件資料
- [ ] 通過驗證後可正常使用三個頁面的全部功能（依 001 規格）
- [ ] 驗證方式（本版採 B；若維運日後確認可於伺服器端把關，另開規格評估改採 A）：
  - **A. 由 BPM／網頁伺服器把關**：沿用 BPM 登入或對放置目錄設定帳號密碼
  - **B. 共用密碼**：頁面要求輸入一組共用密碼後才能解開資料（**本版採用**）

### US-004: 維運者管理存取密碼（僅在 US-003 採 B 時適用）
```
身為儀表板維運者,
我希望能更換共用密碼,
以便人員異動或密碼外洩時能讓舊密碼失效。
```

**驗收標準**:
- [ ] 更換密碼後，下一次更新起舊密碼無法再解開資料
- [ ] 同一瀏覽器分頁內驗證一次即可切換三個頁面；關閉分頁後需重新輸入
- [ ] 密碼錯誤時顯示明確提示，不透露任何案件資料

### US-005: 會議頁可設定為唯讀
```
身為儀表板維運者,
我希望會議頁的編輯與存檔功能可以依設定開關，預設關閉,
以便在確認需要之前，所有人看到的燈號都一致取自工作表，不會因各自電腦的本機紀錄而不同。
```

**驗收標準**:
- [ ] 預設為唯讀：燈號只顯示不可點選，無「更新」按鈕與操作欄，無法開啟編輯
- [ ] 唯讀時不讀取也不寫入本機會議紀錄，燈號一律為原表燈號
- [ ] 唯讀時燈號統計、篩選、搜尋、排序照常可用；頁面說明改為唯讀文字
- [ ] 設定開啟後，行為與 001 規格（US-006）相同

## 6. 驗收場景 (Acceptance Scenarios)

### 場景 SC-001: 排程自動更新（正常）
```
Given: 工作表四個分頁內容合規，線上為上一版資料
When:  排程時間到
Then:  儀表板更新為工作表最新內容，擷取日期為當日
And:   更新紀錄記下「排程」、時間與各分頁件數
```

### 場景 SC-011: 成功也通知（正常）
```
Given: 工作表四個分頁內容合規
When:  排程更新成功
Then:  Owner 收到主旨為「工作表更新成功（日期）」的 Email，內含各分頁件數與下載連結
And:   信中不含存取密碼、寄信帳號密碼等任何 Secret
```

### 場景 SC-012: 自動發佈網站（正常）
```
Given: 排程更新成功
When:  開啟 https://pmo-sync.evanwang.cc/
Then:  轉到案件追蹤頁並要求輸入存取密碼
And:   輸入密碼後看到本次更新的資料；通知 Email 附網站網址
```

### 場景 SC-013: 頁首導覽切換三頁（正常）
```
Given: 使用者已輸入密碼開啟案件追蹤頁
When:  點頁首導覽的「管理層呈報」，再點「IT 內部會議」
Then:  依序進入該頁，不需重新輸入密碼
And:   導覽標示目前所在頁
```

### 場景 SC-002: 手動觸發（正常）
```
Given: 維運者在會議前發現工作表剛更新
When:  維運者手動觸發一次更新
Then:  儀表板更新為最新內容，更新紀錄記下「手動」
```

### 場景 SC-003: 資料錯誤不上線（錯誤）
```
Given: Project 分頁第 10 列的 Progress 被填成「約九成」
When:  排程更新執行
Then:  本次更新不發佈，線上維持上一版
And:   通知內容為「Project 分頁第 10 列 Progress「約九成」無法辨識」
```

### 場景 SC-004: 分頁缺欄（邊界）
```
Given: SAP 分頁尚未加上 Progress 與燈號欄
When:  排程更新執行
Then:  儀表板照常更新，SAP 案件完成度顯示未提供、燈號為待評估
And:   通知中列出「SAP 分頁尚未有 Progress 與燈號欄」
```

### 場景 SC-005: 工作表無法讀取（錯誤）
```
Given: 工作表的讀取授權被移除或工作表暫時無法連線
When:  排程更新執行
Then:  本次更新不發佈，線上維持上一版，並通知無法讀取的原因
```

### 場景 SC-006: 未授權者無法取得資料（安全）
```
Given: 某人知道儀表板網址但未通過驗證
When:  開啟任一頁面，或直接下載頁面檔案、檢視原始碼與傳輸內容
Then:  看不到也搜尋不到任何案件名稱、負責人或 LOG 內容
```

### 場景 SC-007: 通過驗證後正常使用（正常）
```
Given: 授權人員開啟案件追蹤頁
When:  通過驗證
Then:  可使用 001 規格的全部功能
And:   （採 B 時）在同一分頁切換到管理層呈報與會議頁不需再次輸入
```

### 場景 SC-008: 密碼錯誤與更換（錯誤／邊界，僅採 B 時）
```
Given: 維運者已更換共用密碼並完成一次更新
When:  使用者輸入舊密碼
Then:  顯示「密碼不正確」，不顯示任何案件資料
```

### 場景 SC-009: 會議頁唯讀（預設）
```
Given: 未開啟會議編輯設定，且使用者瀏覽器中留有先前的本機會議紀錄
When:  開啟會議頁
Then:  燈號一律為原表燈號，沒有「更新」按鈕，燈號不可點選
And:   燈號統計、篩選、搜尋、排序照常可用
```

### 場景 SC-010: 開啟會議編輯（正常）
```
Given: 已開啟會議編輯設定
When:  開啟會議頁並修改某案件燈號後儲存
Then:  行為與 001 規格 SC-007 相同
```

## 7. 範圍限制 (Out of Scope)

> 以下內容明確排除在此功能之外：

- 頁面開啟時即時讀取工作表（資料仍以排程或手動更新的快照為準）
- 會議燈號、風險、下一步回寫工作表或跨電腦同步
- 個人帳號、角色權限、個別停權、登入紀錄
- 三個頁面的畫面與操作行為變更（沿用 001）
- 工作表本身的欄位調整（由資料維護者負責；本功能只讀取）
- 任何 CMS（`cms/`）的修改
