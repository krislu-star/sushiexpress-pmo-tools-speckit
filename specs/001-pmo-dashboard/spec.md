## 1. 概述 (Overview)

爭鮮資訊部各小組（Frontend、Project、BPM、SAP）目前以一份共用週報工作表追蹤 IT 案件，閱讀與彙整都仰賴人工翻表。本功能提供三個以工作表資料為基礎的頁面：**一般案件追蹤**、**主管專案面板與呈報**、**IT 內部會議**，讓同仁快速查到案件進度、讓主管整理成可列印的 A4 呈報給副董、讓內部會議以燈號聚焦需協調的案件。

## 2. 問題陳述 (Problem Statement)

**目前狀況**：案件資訊散落在各小組分頁，欄位多、LOG 冗長；主管要呈報時需手動摘錄並排版；內部會議沒有統一的風險燈號與下一步紀錄。

**期望狀況**：同一份資料以三種角色視角呈現——一般同仁可搜尋、篩選、排序案件並查閱完整 LOG；主管可依原表分類彙整專案、挑選並排序呈報內容後列印；會議中可替案件標記燈號、風險與下一步。

**影響範圍**：資訊部各小組同仁、資訊主管、呈報對象（副董）、IT 內部會議與會者。

## 3. 使用者故事 (User Stories)

### US-001: 查詢與追蹤案件
```
身為資訊部同仁,
我希望在單一列表中搜尋、篩選並排序各小組的 IT 案件,
以便快速掌握特定案件或小組的最新處理進度。
```

**驗收標準**:
- [ ] 列表顯示案件名稱、專案／分類、工作類型、承辦小組、負責人、狀態、完成進度、進度紀錄（LOG 前三個非空行）、更新日期
- [ ] 可用關鍵字搜尋（比對 BPM 單號、案件名稱、負責人、工作類型、完整 LOG）
- [ ] 可依所屬專案、小組、狀態篩選，並可一鍵重設
- [ ] 可點欄名切換升冪／降冪；可依 BPM 單號排序；可回到原表順序
- [ ] 顯示目前排序欄位與方向，以及符合條件的件數

### US-002: 查閱案件完整內容
```
身為資訊部同仁,
我希望點選案件後看到完整 LOG 與來源位置,
以便確認細節或回到原始工作表核對。
```

**驗收標準**:
- [ ] 詳細內容顯示狀態、完成進度、專案／分類、工作類型、負責人、預計完成、更新日期與原表完整 LOG
- [ ] 標示來源小組分頁與原表列號，並提供可開啟原始工作表對應列的連結
- [ ] 原表無 LOG 時顯示「原表尚無 LOG」

### US-003: 主管以專案視角檢視
```
身為資訊主管,
我希望以「小組｜原表 Project/Catalog」彙整的專案列表檢視整體方向,
以便不必逐案閱讀即可掌握各專案進展與聯繫對象。
```

**驗收標準**:
- [ ] 專案列表每列顯示專案名稱、彙整狀態、進度紀錄彙整（各關聯案件名稱＋最新進度）、關聯案件負責人
- [ ] 原表分類空白者歸入「未分類」
- [ ] 可搜尋專案名稱或內容、依彙整狀態篩選，並可重設
- [ ] 可開啟某專案的關聯案件清單
- [ ] 可切換至「工作列表」，以案件為單位檢視並搜尋案件、專案或負責人

### US-004: 整理並列印管理層呈報
```
身為資訊主管,
我希望勾選要呈報的專案、調整順序並預覽成 A4 報告,
以便直接列印或另存 PDF 呈報給副董。
```

**驗收標準**:
- [ ] 每個專案可切換是否納入呈報，預設全部納入；畫面持續顯示已選數量
- [ ] 未選任何專案時無法預覽或列印
- [ ] 預覽以 A4 直式分頁呈現，每頁最多 2 個專案，含報告標題、呈報對象、資料說明、頁碼
- [ ] 預覽中可用拖曳或鍵盤（上／下、Home／End）調整順序，Esc 取消拖曳；順序變更有螢幕閱讀器可讀的提示
- [ ] 列印輸出只包含報告頁，不含頁首、操作按鈕與拖曳把手

### US-005: 聯繫負責人（示意）
```
身為資訊主管,
我希望從專案或案件直接發起與負責人的 Teams 對話,
以便快速詢問進度。
```

**驗收標準**:
- [ ] 專案與案件皆提供「Teams 聯繫」入口
- [ ] 負責人尚未設定 Teams 帳號時，顯示說明視窗，明確告知「未開啟或傳送任何訊息」
- [ ] 本版所有負責人皆視為未設定 Teams 帳號（帳號對照暫不處理）

### US-006: 內部會議以燈號聚焦
```
身為 IT 內部會議與會者,
我希望替每個案件標記燈號、風險／需要協助、下一步與預計完成日,
以便會議先處理需要協調的案件並留下結論。
```

**驗收標準**:
- [ ] 燈號分為紅燈、黃燈、綠燈、待評估；初始為原表燈號欄的值，原表空白時為待評估
- [ ] 會議中修改的燈號優先於原表燈號，並標示為「本機修改」
- [ ] 頁首統計各燈號件數，點選可篩選該燈號，再點一次取消
- [ ] 預設排序為紅燈 → 黃燈 → 待評估 → 綠燈；各欄可切換排序；空值一律排在最後
- [ ] 可搜尋案件、負責人、進度紀錄、風險、下一步；可依小組與燈號篩選；可一鍵重設篩選與排序
- [ ] 編輯後儲存會記錄當日為更新日期，並顯示儲存結果提示
- [ ] 預計完成日保留原文字，可改填 YYYY-MM-DD

### US-007: 了解資料界線
```
身為任何使用者,
我希望清楚知道畫面資料的來源、擷取日期與哪些是示意值,
以便不誤把展示資料當成正式進度。
```

**驗收標準**:
- [ ] 各頁顯示資料擷取日期、資料說明橫幅與案件總數
- [ ] 頁首提供「關於這個版本」說明，列出資料範圍、示意值與尚未串接的功能
- [ ] 完成度與燈號來自原表、空白者顯示未提供／待評估；Teams 聯繫、會議本機儲存皆有文字標示

## 5. 非功能需求 (Non-Functional Requirements)

| ID | 類別 | 需求描述 |
|----|------|---------|
| NFR-001 | 效能 | 以四組全部案件（設計上限 500 件）的快照，頁面開啟後 2 秒內可操作；搜尋、篩選、排序結果即時更新（< 100ms 感知延遲） |
| NFR-002 | 可用性 | 所有操作可用鍵盤完成；按鈕、表單與排序狀態提供輔助科技可讀標籤；遵循 WCAG 2.1 AA 對比度；尊重「減少動態效果」偏好 |
| NFR-003 | 安全性 | 頁面含真實工作資料，僅能部署於 BPM 指定展示空間（**002 起修訂**：改為發佈至公開網址並以共用密碼加密保護，見 `specs/002-pmo-data-sync-and-access/spec.md` FR-013、NFR-003）；不得內嵌任何憑證或金鑰；搜尋與編輯輸入不得被當作可執行內容顯示 |
| NFR-004 | 相容性 | 支援 Chrome（桌機與手機，最新兩個主要版本）；其他瀏覽器不保證。需符合 BPM 的內容安全政策（CSP）與 iframe 限制（見第 8 節假設） |
| NFR-005 | 列印 | 列印輸出為 A4 直式，每頁版面固定、案件不跨頁斷開，進度條與狀態在黑白列印下仍可辨識 |
| NFR-006 | 在地化 | 介面文字為繁體中文；中文排序採自然順序（數字依數值比較） |

## 6. 驗收場景 (Acceptance Scenarios)

### 場景 SC-001: 搜尋並查閱案件（正常）
```
Given: 使用者在案件追蹤頁，列表顯示快照中四組全部案件
When:  輸入關鍵字「POS」
Then:  列表只顯示名稱、單號、負責人、類型或 LOG 含「POS」的案件，件數同步更新
And:   點選「POS優化」後，詳細內容顯示完整 LOG 與 Frontend 原表第 2 列的連結
```

### 場景 SC-002: 排序與缺值（邊界）
```
Given: 使用者在案件追蹤頁
When:  點「更新日期」欄名排序
Then:  更新日期未提供的案件維持原表列序並排在最後
When:  點「完成進度」兩次
Then:  依完成進度降冪排列，欄名標示為降冪
```

### 場景 SC-003: 查無結果（錯誤／空狀態）
```
Given: 使用者在案件追蹤頁
When:  輸入不存在的關鍵字
Then:  顯示「找不到符合條件的案件」與「清除篩選」按鈕
And:   點「清除篩選」後恢復顯示快照中全部案件
```

### 場景 SC-004: 主管呈報與列印（正常）
```
Given: 主管在專案面板，全部專案預設納入呈報
When:  取消其中兩個專案並點「預覽報告」
Then:  預覽只包含其餘專案，每頁最多 2 個，頁尾顯示「n / 總頁數」
When:  以鍵盤將第一個專案下移一位
Then:  報告順序同步更新，並朗讀「已移至第 2 位」
And:   列印輸出只包含報告頁
```

### 場景 SC-005: 未選任何專案（邊界）
```
Given: 主管在專案面板
When:  取消所有專案的呈報勾選
Then:  「預覽報告」按鈕為不可用，已選數量顯示 0
```

### 場景 SC-006: Teams 帳號未設定（錯誤）
```
Given: 某專案的負責人尚未設定 Teams 帳號
When:  主管點「Teams 聯繫」
Then:  顯示說明視窗，告知尚未完成設定且未開啟或傳送任何訊息
And:   關閉後回到原專案列表狀態
```

### 場景 SC-007: 會議燈號編輯與保存（正常）
```
Given: 與會者在會議頁，某案件原表燈號為綠燈
When:  將該案件改為紅燈、填寫風險與下一步並儲存
Then:  該案件排在列表最前，紅燈統計為 1，更新日期為今天
And:   重新整理頁面後仍保留該修改，並提示「未回寫工作表」
```

### 場景 SC-008: 本機儲存不可用（錯誤）
```
Given: 瀏覽器封鎖本機儲存（如無痕模式限制）
When:  與會者儲存燈號修改
Then:  畫面仍套用修改，並提示「修改僅保留至離開此頁」
And:   頁面其他功能正常運作
```

### 場景 SC-009: 本機資料損毀（錯誤）
```
Given: 本機已保存的會議資料有一筆格式不符（例如燈號值不存在）
When:  開啟會議頁
Then:  忽略該筆，其餘有效紀錄正常套用，頁面不中斷
```

### 場景 SC-010: 原表完成度與燈號（正常／邊界）
```
Given: 原表某案件 Progress 為「90%」、燈號為「🟡 黃燈」；另一案件兩欄皆空白
When:  開啟案件追蹤頁與會議頁
Then:  第一個案件顯示完成度 90% 與進度條，會議頁燈號為黃燈
And:   第二個案件完成度顯示「未提供」，會議頁燈號為待評估
When:  原表 Progress 填入無法辨識的值（如「約九成」）或超出 0%～100%
Then:  資料更新時被擋下並指出分頁與列號，不產生錯誤的進度
```

## 7. 範圍限制 (Out of Scope)

> 以下內容明確排除在此功能之外：

- 即時或排程讀取 Google Sheets；資料以指定日期的快照提供
- 會議燈號、風險、下一步回寫工作表，或跨電腦／跨使用者同步
- BPM 登入整合、角色權限、跨角色切換選單（002 起頁首提供三頁導覽，見 002 FR-018；仍無角色權限）
- 實際發送 Teams 訊息；負責人與 Teams 帳號對照表的建立與維護（本版暫不處理）
- 呈報對象切換（固定為副董）
- Chrome 以外瀏覽器的相容性保證
- DW、Infra 小組的案件
- 案件更新日期的來源（原表未提供）
