## 這份檔案是什麼

**一份「這類網站通常該有什麼」的預期清單。** 它是**判斷**（依該類型的常見模式歸納），不是事實——所以每一項的依據都要能講出理由，**絕不寫「約 X% 的同類網站」這種假統計**（違反 SKILL.md 核心紀律「不編造數字」）。

清單分兩種欄位：

- **可重用、跟類型綁定**（本檔預先填好）：`分級`、`判斷依據`、`影響`、`建議`。
- **每個網站各自不同、稽核當下才填**（本檔留白）：`現況證據`、`信心`。

這樣切分，是為了讓「判斷依據」與「現況證據」在報告裡**分成兩行**——客戶一眼分辨哪些是「依某類型常見模式的判斷」、哪些是「這次真的爬到的證據」。

## 分級的意思（只用這三級）

| 分級 | 意思 |
|---|---|
| **幾乎必備** | 這類網站幾乎都該有；缺了通常是明確缺口。 |
| **視情況** | 依商業模式／規模／目標而定；列出來讓稽核依現況判斷要不要算缺口。 |
| **通常不需要** | 這類網站多半不需要。**主動寫進報告**——「這個你不需要做」能避免報告只會膨脹專案範圍（SKILL.md:318）。 |

## 每一項的格式（對齊 Phase 7 報告格式）

```
### 項目名稱
- 分級：幾乎必備 / 視情況 / 通常不需要
- 判斷依據：<為什麼這類網站通常需要／不需要它>（判斷，非本次爬取證據）
- 影響：<缺少時對客戶的商業影響>
- 建議：<若要補，往哪個方向補>
- 現況證據：〔稽核時填入——指回 URL 或截圖編號；沒爬到就標「未涵蓋」，不要用「看起來應該有」補足〕
- 信心：〔稽核時填入——高 / 中 / 低〕
```

## 撰寫紀律（沿用 SKILL.md）

1. **不編造數字**——判斷依據寫理由（「非營利常見的經常性收入模式」），不寫百分比或「業界標準是」。
2. **清單是提示與 backstop，不是封閉窮舉**——現場若發現這個網站有清單外的重要缺口，照樣記下來（白話名＋依據），別因為不在表上就丟掉。
3. **「通常不需要」一定要有一段**——這是這份清單的價值之一，不是可省略的補充。
4. **碰到 out-of-scope 的項目：只標「觀察」、指向專門工具，不當成已稽核的缺口。** SKILL.md「刻意不做的」列了四塊本 skill 刻意不做的事——**效能與 Core Web Vitals、完整無障礙稽核、SEO 全項、行為數據**。這些領域的預期項目若要列進清單，`分級` 用「視情況」、`建議` 一律寫成「僅標記為觀察；正式評估另接 {工具}」（效能→Lighthouse、a11y→專門 a11y 稽核、行為→GA4／錄影工具），**不要**寫成好像本 skill 完整驗過。措辭對齊 `media.md` 的「頁面載入速度」一項。
5. 累積數十份 `pages.json` 後，「幾乎必備」的依據可從「判斷」升級為「實際統計」——**介面不變**，只是把「常見模式」換成有數據支撐的敘述。
