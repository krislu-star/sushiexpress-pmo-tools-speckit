# 預期清單：SaaS (saas)

> Phase 7 機會缺口的比對基準。格式與撰寫紀律見 [`_template.md`](./_template.md)。
> 對應 Phase 0 類型：**SaaS**　·　最後更新：2026-08-13

**這類網站是什麼：** 軟體即服務的行銷官網（多為訂閱制產品的門面，不含產品本體）。核心任務是**講清楚產品解決什麼問題、建立信任、把訪客推進到「註冊試用」或「預約 Demo／聯絡銷售」**。

**每項的 `現況證據` 與 `信心` 留白，稽核時填入。**

## B. 內容與資訊架構

### 產品價值主張（首屏講清楚解決什麼問題）
- 分級：幾乎必備
- 判斷依據：SaaS 訪客決策快，首屏若沒講清楚「這能幫我解決什麼」就會跳出。
- 影響：價值不清＝高跳出、低試用轉換。
- 建議：一句話講清楚受眾、問題、價值；佐產品畫面。

### 功能介紹
- 分級：幾乎必備
- 判斷依據：訪客需要知道產品實際能做什麼才會評估。
- 影響：功能講不清會讓評估者無法判斷是否符合需求。
- 建議：以「功能對應到的價值／使用情境」呈現，而非規格堆疊。

- 影響：無定價或過度隱藏會讓自助型客戶卻步。
- 建議：方案比較表；企業方案可用「聯絡我們」。

## C. 信任與社會證明

### 社會證明（客戶 logo／證言／案例）
- 分級：幾乎必備

- 影響：缺少會讓新訪客缺乏採用信心。
- 建議：客戶 logo 牆、具名證言、可量化的案例研究。

## D. 轉換機制（SaaS 的核心）

### 主要 CTA：註冊試用 或 預約 Demo
- 分級：幾乎必備
- 判斷依據：SaaS 網站的存在目的就是把訪客送進試用或銷售漏斗。
- 影響：CTA 不明確＝流量無法轉成試用／商機。
- 建議：全站一致的主 CTA；依模式選「免費試用」或「預約 Demo」。

- 信心：

### 登入入口
- 分級：幾乎必備
- 判斷依據：既有用戶需要從官網進入產品，是基本動線。
- 影響：登入入口難找會造成既有用戶困擾。
- 建議：導覽列固定放登入入口，與註冊區分。
- 現況證據：
- 信心：

### 免費試用 vs Demo 預約（模式選擇）
- 分級：視情況
- 判斷依據：自助成長（PLG）走免費試用／免費方案；銷售導向（sales-led）走預約 Demo／聯絡銷售。兩者動線不同。
- 影響：模式與 CTA 不搭（如高單價企業產品只給自助試用）會錯配客群。
- 建議：依產品單價與銷售模式選對主要轉換路徑。

## 通常不需要（SaaS 多半不用做）

### 購物車式一次性結帳
- 判斷依據：SaaS 多為訂閱制，計費在產品內或由銷售處理，非電商式結帳。
- 說明：官網負責把人送進試用／洽詢，實際計費交給產品內的訂閱流程。

### 實體據點／地圖
- 判斷依據：純線上產品的評估不依賴實體位置。
- 說明：除非有在地服務或法遵揭露需求，否則不需據點地圖。
