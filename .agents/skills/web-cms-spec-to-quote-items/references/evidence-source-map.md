# 證據 → 檢核表 對映（證據優先收件用）

把每一份已存在的產物，對到它能覆蓋的檢核表格。目的：**不叫人填 32 格，而是拿現成材料自動評覆蓋率，只補真正影響報價的缺口。**

## 常見材料 → 覆蓋哪些格

| 材料類型 | 典型覆蓋的檢核表格 | 備註 |
|----------|--------------------|------|
| **網站體驗 audit 報告**（web-experience-audit） | §1 現況盤點幾乎全包：URL(1.1)、sitemap/頁面清單(1.2)、模板區塊盤點(1.3)、使用者旅途(1.4)、技術棧(1.8)、流量線索(1.7)；部分 §3 內容類型(3.1) | 改版案的第一節可幾乎不用人工填 |
| **客戶 RFP / 改版需求文件** | §2 需求(2.1)、§3 內容模型主結構(3.1/3.2/3.3)、部分 §4 邊界 | 保留原文；模糊語句轉待確認，別翻成工項 |
| **第三方技術文件**（金流／CRM／電子報 API 指南） | §4.1 第三方整合（串接方式、帳號、合規如 PCI/ADA） | 用來定金流 SCP 與 PCI 責任範圍 |
| **往來對話 / 訊息**（如業務窗口 chat） | §2.5 參考網站含原因、§3.4 多語、§4.4 SEO 分工、§5 商業脈絡、遷移/後台等決策訊號 | 最常藏「衝突」與「模糊語句」，逐句檢視 |
| **現況實測**（Playwright / 手動走查） | 驗證 audit 的「待確認」項（輪播張數、是否動態統計、比較表內容等） | 把推測降為事實，收斂 §1/§3 |
| **舊後台截圖 / 欄位清單** | §1.5 現有 CMS、§1.6 使用中 vs 閒置、§4.3 遷移來源 | 決定遷移難度與後台重建範圍 |

## 覆蓋率評分

逐格標 `✓ 已覆蓋` / `△ 部分` / `✗ 缺`，`✓`=1、`△`=0.5、`✗`=0，加總 ÷ 滿分（改版 32／全新 24）。落點對應閘門見 SKILL.md 步驟 0。

## 只問「缺且影響報價」的格（精準追問）

補完覆蓋率後，缺口分兩種：
- **影響報價的硬缺口** → 生成精準追問（通常 6–10 題）。優先問這些：資料遷移範圍、後台維護角色與自助編輯範圍、多語×地區矩陣、主機/部署歸屬、金流串接方式與帳號、SEO 分工邊界、商業框架（預算/死線/驗收/簽核）、以及文件「引用卻未附」的**主數據**（價目/品項/功能矩陣，常是最大變數）。
- **不影響報價結構的缺口** → 直接進待確認假設清單，不擋出初版。

## 收到答案後：重新偵測衝突與新工項

答案常會**改變案子量級**或**與既有材料矛盾**，務必重掃：
- 「要雙語」→ 單語成本翻倍，語系獨立成工項。
- 「自建後台（含訂單/會員/產品/金流）」→ 案子從「官網+CMS」升級為「電商營運平台」，報價數量級不同。
- 文件寫「多國合規」但窗口說「只做兩地區」→ 標待確認，不擅自選一邊。
- 頁面文案的整合商名稱 ≠ 實際要串的服務 → 標明是文案而非整合範圍。
