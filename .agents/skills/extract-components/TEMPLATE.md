# COMPONENTS.md Output Template

This file defines the exact structure an agent must produce when writing `references/COMPONENTS.md`.
Replace all `[placeholder]` values with extracted content.

```markdown

> Extracted from `[PROTOTYPE_DIR]`. Token references follow `references/DESIGN.md`.
> Generated by the `extract-components` skill — do not edit manually.

## [ComponentName]

**Props**: `[prop: TypeA | TypeB]`, `[prop?: type]`, `children: React.ReactNode`
```

## Rules

- One `##` section per canonical role, listed in **alphabetical order**
- **Props**: write as TypeScript prop signature. Use union literals for any variant with multiple values found in source. Include `children: React.ReactNode` for components that wrap arbitrary content (e.g. Card, Modal, Nav, Avatar). Omit `children` for self-contained display components (e.g. Badge, Spinner). When in doubt: if the prototype renders child content inside the component, include it. Place `children` as the last required prop, before optional props like `onClick`.
- **States**: comma-separated list of all CSS class variants collected during scanning — including both visual variants (e.g. `primary, secondary, ghost`) and interactive states (e.g. `hover, disabled, loading`). Use plain English names without dashes or double-dashes (e.g. `primary, secondary, disabled` — not `btn-primary` or `--disabled`). Use `default` to label the base unstyled state when no explicit class covers it.
- **Token refs**: prose description using `{section.key}` syntax. Only list tokens that were actually matched — do not invent.
- **File**: always the path under `src/components/shared/`. Must match the actual generated `.tsx` file name.
- Components are listed in **alphabetical order** by canonical role name.
- Do not add sections for components that were discarded (no canonical role match).
- If zero components were extracted, write only the header block (the `>` lines) and no `##` sections. Add: `> No reusable component patterns were found in this prototype.`
